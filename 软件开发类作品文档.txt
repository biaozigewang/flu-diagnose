第一章 需求分析
================================================================================

1.1 开发背景与意义

问题现状：
甲型流感高发季节，患者缺乏快速自检工具
传统问诊流程冗长（12-15个问题），用户体验差
基层卫生机构诊断能力不足，需要辅助决策工具
疫情监测需要大量初步筛查数据

开发目标：
设计一个AI驱动的流感诊断辅助系统，帮助用户快速自检是否可能感染甲型流感，并给出就医建议。

1.2 竞品分析

维度                本作品              丁香医生          春雨医生          平安好医生
诊断算法            A*+模糊推理+贝叶斯  规则库            规则库            深度学习
问诊效率            4-6题(节省50-65%)   12-15题           10-12题           8-10题
图像分析            支持咽喉图像        不支持            不支持            支持但需付费
推理可视化          知识图谱+规则链     不支持            不支持            不支持
离线使用            支持                不支持            不支持            不支持
开源                MIT开源             不开源            不开源            不开源
部署成本            低(Flask+SQLite)    高                高                高

竞争优势：
1. 效率最优：A*算法相比竞品节省50-65%的问题数
2. 算法透明：三引擎融合，推理过程完全可视化
3. 成本最低：开源、轻量级部署，适合基层机构
4. 创新性强：A*在医疗问诊中的创新应用

1.3 用户与功能

目标用户：
个人用户：快速自检是否需要就医
社区卫生机构：初步筛查工具
学校卫生室：学生健康监测
疾控部门：疫情监测数据收集

主要功能：
1. 症状输入（聊天/表单/图像）
2. A*智能问诊（最优路径规划）
3. 多引擎诊断推理
4. 诊断结果展示（风险等级、置信度、规则链）
5. 历史记录管理与对比
6. 数据导出（CSV/PDF）

指标                目标        实现
诊断准确率          ≥85%        87.3% ✓
平均问题数          ≤6题        4.8题 ✓
效率提升            ≥50%        60% ✓

3.3 关键算法

3.3.1 A*问诊算法

状态表示：
@dataclass
class DiagnosisState:
    f_score: float              # f(n) = g(n) + h(n)
    g_score: int                # 已问问题数
    confidence: float           # 当前置信度
    path: List[str]             # 问题序列
    known_symptoms: Dict        # 已知症状

启发式函数：
h(n) = (目标置信度 - 当前置信度) / 平均信息增益

信息增益计算：
IG(symptom) = Σ P(symptom=yes|known) * log(P(flu|symptom=yes))
            + P(symptom=no|known) * log(P(flu|symptom=no))

效果：
平均问题数：4.8题（vs 顺序问诊12题）
效率提升：60%
诊断准确率：87.3%

3.3.2 模糊推理引擎

规则示例：
IF 发热(高) AND 肌肉酸痛(是) AND 急性起病(是)
THEN 甲流(可能性=0.85)

置信度融合：
confidence = Σ(rule_weight × rule_confidence) / Σ(rule_weight)

3.3.3 贝叶斯网络推理

条件概率表：
P(甲流|发热,肌肉酸痛,急性起病)
= P(发热|甲流) × P(肌肉酸痛|甲流) × P(急性起病|甲流) × P(甲流)
  / P(发热,肌肉酸痛,急性起病)

后验概率计算：使用变量消除算法

第五章 安装及使用
================================================================================

5.1 环境要求

操作系统：Windows 10+, macOS 10.15+, Linux (Ubuntu 18.04+)
Node.js：16.0+
Python：3.8+
SQLite：3.0+
浏览器：Chrome 90+, Firefox 88+, Safari 14+

5.2 安装过程

5.2.1 前端安装
cd frontend
npm install
npm run dev          # 开发模式，访问 http://localhost:5173
npm run build        # 生产构建

5.2.2 后端安装
cd backend
pip install -r requirements.txt
cp api_config.example.py api_config.py
# 编辑 api_config.py，填入 DeepSeek API Key
python app.py        # 启动服务，访问 http://localhost:5000

5.2.3 Docker部署（可选）
docker-compose up -d
# 前端：http://localhost:3000
# 后端：http://localhost:5000

5.3 主要使用流程

5.3.1 聊天式诊断
1. 打开应用 → 点击"立即自检"
2. 在聊天框输入症状（如"发烧39度，浑身酸痛"）
3. 系统自动提取症状，显示诊断结果
4. 查看风险等级、置信度、建议
5. 保存诊断记录

5.3.2 A*智能问诊
1. 打开应用 → 点击"A*智能问诊"
2. 系统自动选择最有价值的问题
3. 用户回答是/否（或输入体温）
4. 重复直到置信度≥85%
5. 查看诊断结果和置信度爬升曲线

5.3.3 图像分析
1. 打开应用 → 上传咽喉图像
2. 系统自动分析图像，识别充血程度
3. 自动填充症状表单
4. 点击"诊断"获取结果

5.3.4 历史对比
1. 打开"历史记录"页面
2. 选择2条诊断记录
3. 查看雷达图对比
4. 导出CSV数据

6.2 克服的困难

6.2.1 困难1：A*启发式函数设计
问题：如何设计既准确又高效的启发式函数？
解决：基于条件概率表推导，通过历史数据验证可容许性
收获：深入理解启发式搜索的本质

6.2.2 困难2：多引擎融合与冲突解决
问题：三个引擎可能给出不同结论
解决：加权投票 + 置信度阈值 + 冲突标记
收获：学会在不确定性下做决策

6.2.3 困难3：医学知识工程
问题：如何准确建模甲流诊断规则？
解决：参考诊疗指南、医学文献、专家评审
收获：理解医学知识的复杂性和不确定性

6.2.4 困难4：图像分析准确性
问题：咽喉图像质量参差不齐
解决：图像预处理 + 质量检查 + 多模型融合
收获：计算机视觉在医疗应用中的挑战
